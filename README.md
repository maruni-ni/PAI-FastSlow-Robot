# Fast/Slowロボット v2 - Adaptive Sensing

提出用リポジトリ: https://github.com/maruni-ni/PAI-FastSlow-Robot

ゴールへの軽量な制御と、障害物への接近時の学習モデルによる左右判断を切り替えるロボットの概念実証です。粗い5本センサで判断が曖昧な場合にだけ、停止したまま13本の詳細観測を追加します。**視点変更を伴うActive Perceptionではなく、Adaptive Sensing（適応的観測）**です。

## 新しいPCでの導入と実行

検証環境はWindows x64 / Python 3.11.16。Python 3.11と、PyBullet構築用のMicrosoft C++ Build Tools（この環境では既存Visual Studio 2022）を用意してください。公式PyBullet 3.2.7のWindows wheelをこの検証では利用できず、ソースビルドしています。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py --scenario left_open --method adaptive --gui --realtime
```

学習済みモデルを同梱しているため、学習をやり直さず実行できます。joblibモデルは信頼できるこのパッケージのものだけを読み込んでください。

GUIのない環境では `--gui --realtime` を省くと、描画なしで同じ制御・センサ・接触確認を実行します。`main.py` は到達で終了コード0、失敗で1を返します。

```powershell
.\.venv\Scripts\python.exe main.py --scenario right_open --method adaptive
.\.venv\Scripts\python.exe main.py --scenario ambiguous_right --method adaptive
.\.venv\Scripts\python.exe main.py --scenario single --method event
.\.venv\Scripts\python.exe view_demo.py
```

`view_demo.py` は同梱の最終比較ログを再生します。追加観測の前後は説明用に2秒静止し、qキーかウィンドウを閉じて終了します。`デモを見る.cmd` からも開けます。

依存の主要バージョンは `requirements.txt`、作成時の全バージョンは `requirements-lock.txt`。画像・動画・PDFの生成はWindows標準フォント（游ゴシック/MSゴシック）を使うため、他OSではフォントパスの変更が必要です。

## 動作と学習モデル

```text
FAST → SLOW_DECIDE → [曖昧なら SLOW_REOBSERVE] → SLOW_AVOID → FAST → GOAL
```

- FAST: ゴール方位へのフィードバック制御。AIを呼ばない。
- DECIDE: 前方の距離が1.2m未満かつゴールへの通路が塞がると停止し、粗モデルを1回呼ぶ。
- REOBSERVE: 最大モデル確率が0.80未満なら、停止したまま13本を追加計測し詳細モデルで1回だけ再判断。
- AVOID: 出力の左右を旋回角の符号に反映。方向を保持して70度旋回し、通過する。ゴール通路3本レイの空きが0.45秒続き、接近時よりゴールへ近づけばFASTへ戻る。
- 安全処理: 形状間隔0.06m未満、回避25秒超過、全体60秒で失敗停止。接触や未到達を成功には数えない。

センサ契約は `sensor_config.py` に一元化しています。粗角度は `[90,45,0,-45,-90]`、詳細は90度から-90度まで15度刻みの13本、距離上限4m、始点は中心から0.43m。正面添字や扇形の範囲もここで定義します。読込モデルの角度順・特徴数・正規化を照合し、不一致なら停止します。

粗・詳細モデルとも、詳細センサの左右の空きを使った同じ幾何学教師で学習しています。教師は左右15-75度の距離の最小値/平均値とゴール方位誤差を評価します。入力は距離を4mで正規化した値と方位誤差のsin/cos（粗7・詳細15特徴）。実行時は教師規則を呼ばず、Random Forestの `predict_proba` 最大クラスを実際の回避方向へ適用します。

合成3000配置と左右鏡映の6000観測を、鏡映対が同じ分割に入るよう配置単位で分割しました。2250配置・4500観測を学習、別750配置・1500観測を分類評価に使用。80本の木、最大深さ14、最小葉5、seed42。教師一致率は粗75.7%、詳細97.8%です。これは規則の再現度であり、走行成功率ではありません。

## 同条件の最終比較

開発用8シーンとは別の24シーン（seed 90000-90005、4種類ずつ）で5方式を比較しました。コード・モデル・配置を初回実行前に `output/final/freeze.json` へ保存し、最終結果を見た制御や配置の調整は行っていません。

| 方式 | 到達 | 接触 | 時間切れ等 | 最小間隔m | 平均推論回数 | 平均詳細スキャン | 平均総レイ |
|---|---:|---:|---:|---:|---:|---:|---:|
| 固定左 | 17/24 | 0 | 7 | 0.333 | 0 | 0 | 4722.0 |
| 固定右 | 17/24 | 0 | 7 | 0.333 | 0 | 0 | 4722.0 |
| 粗観測1回 | 22/24 | 0 | 2 | 0.333 | 1.25 | 0 | 4291.3 |
| 適応的観測 | 22/24 | 0 | 2 | 0.442 | 1.75 | 0.50 | 4301.8 |
| 常時詳細観測 | 22/24 | 0 | 2 | 0.442 | 1.25 | 536.42 | 11264.8 |

固定左/右は推論せず方向固定。粗観測1回は**v2で同じ教師を使って再学習した粗モデル**を使い、旧版の保存モデルを完全再現する比較ではありません。常時詳細観測は毎制御ステップで13本を追加しますが、AI推論はイベント時のみです。全方式で移動制御・安全・終了条件を共通にしています。

**到達率は粗観測より改善しませんでした。** 全試行の最小間隔は0.333mから0.442mへ増加。適応的観測の総レイ数は常時詳細観測より61.8%少なく、24試行中12試行は追加観測なし、12試行は各1回でした。粗観測と比べると追加観測・追加推論の費用が増えます。

最終比較のseed90004の左右壁2シーンは全方式が時間切れでした。**全120試行・全失敗を保持**しており、これらを分母から外していません。狭い配置などへの適応は未解決です。

総レイには、毎制御の粗5本、必要時の詳細13本、ゴール通路確認3本を全て計上します。形状接触照会はレイではなく、ループ実測時間へ含まれます。

| 方式 | 平均AI処理ms/試行 | 平均ループ処理ms/試行 |
|---|---:|---:|
| 固定左 | 0.00 | 59.43 |
| 固定右 | 0.00 | 59.95 |
| 粗観測1回 | 1.66 | 56.22 |
| 適応的観測 | 2.21 | 56.23 |
| 常時詳細観測 | 1.62 | 74.71 |

`perf_counter`で各方式を1回ずつ測定し、方式の順をシーンごとに乱択しました。ループ時間はセンサ、接触照会、推論、制御、メモリ内ログを含み、ワールド初期化、モデル読込、ディスク保存、描画は除きます。単一PCの短い計測で、厳密な速度優位や省電力を示す結果ではありません。

分類用の配置分割と、走行用の開発/最終分割は別のものです。最終シーンも同種の限定的な合成配置であり、実世界や別環境への一般的な成功率とは主張しません。

## 再現・検証・再生成

```powershell
.\.venv\Scripts\python.exe evaluate.py --split dev
.\.venv\Scripts\python.exe verify.py
.\.venv\Scripts\python.exe sensitivity.py
.\.venv\Scripts\python.exe make_video.py
.\.venv\Scripts\python.exe make_report.py
```

`verify.py` は左右の選び分け、固定誤側の失敗、粗センサでは同じ観測となる左右対、詳細観測後の判断変更、明瞭時の追加観測なし、停止中の観測、学習用解析レイと実PyBulletレイの一致を確認します。

最終結果は同梱しています。`evaluate.py --split final` は既存の `output/final` を上書きしません。最終比較を再実行する場合は、別の作業コピーで既存 `output/final` を明示的に別名へ退避してから実行してください。過去の結果を削除する必要はありません。再学習は `train_model.py` ですが、同梱結果を再現する際は先にモデルを変更しないでください。

`sensitivity.py` は1つの詳細観測の各センサを最大距離4mへ置換し、`P(LEFT)` の変化を求めます。+30度の置換で+0.489の変化があり、動画中ではそのレイを赤で強調します。これは置換方法に依存する局所入力感度で、因果説明や安全性の証明ではありません。走行とは別のオフライン14推論で、走行コストに混ぜていません。

## 限界と元の完成版

PyBulletの平面運動学で、位置・姿勢を直接更新します。実機・車輪の動力学・VLA・動的障害物・迷路・電力は未検証。ゴール座標は既知で、通路確認レイはゴールまで届きます。未校正確率の0.80は暫定閾値で、低確率を実際の危険確率とは解釈しません。詳細モデルの判断が誤る場合もあります。

旧版は別フォルダへそのまま保持し、旧ZIP/動画/PDFのハッシュが変わっていないことを確認しています。ローカル復元情報は公開ZIPに含めない `private/restore-map.json` に保存します。このPCだけは旧版の `.venv311` を変更せず利用でき、`デモを見る.cmd` がその環境も検出します。

正式課題PDFの条件は、この実装では独立に取得・照合していません。PyBullet/ROSなどに関する提出要件は公式案内を確認してください。
